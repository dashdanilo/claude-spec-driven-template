# .claude/context/

Persisted context artifacts generated by skills and subagents. Contents are gitignored (varies per developer and per moment). Only this README is versioned.

## Files that live here

- **`repo-map.md`** - The panoramic-context artifact. A small, deterministic map (directory tree with per-directory file counts, entry points, test locations, the commands block from `AGENTS.md`), generated by `baseline/scripts/repo-map.sh`. `codebase-explorer` regenerates it fresh on every use; there is no cache and nothing to go stale, so it is not classified for freshness the way the old snapshot was. Typically low thousands of tokens even on a repo with 1000+ tracked files, since it grows with directory count, not file content. See `docs/decisions/0003-repo-map-over-snapshot.md`.
- **`repomix-snapshot.md`** - A manual, opt-in export of the codebase's actual contents, packed into one file by [Repomix](https://github.com/yamadashy/repomix). Generated only when a user explicitly runs the `refresh-snapshot` skill; nothing generates or reads it automatically. On a real repo this routinely lands in the megabytes, tens of times over any usable context budget, so `check-snapshot.sh` enforces a hard size budget (300,000 bytes, ~75k tokens) and refuses to call it usable context above that. Use case: handing a single file to some other tool that has no filesystem access, not something a Claude Code agent reads itself.
- **`config.json`** - Threshold overrides for this project (staleness thresholds for the Repomix size/staleness check, etc). Optional.
- **`last-analyze.log`** - Timestamp of the last `analyze-codebase` run.

## The Repomix size/staleness model

`.claude/scripts/check-snapshot.sh` classifies `repomix-snapshot.md`, when
one exists, from its header metadata:

```
generated_at: 2026-06-23T14:23:00Z
commit_sha: abc123
files_captured: 247
```

| Status | Trigger | What happens |
|---|---|---|
| `too-large` | over 300,000 bytes (~75k tokens) | Checked first, independent of staleness. Never read as context; grep it or delete it. |
| `fresh` | under budget, < 5 files changed AND < 3 days old | Fine to read directly if you genuinely need this export |
| `stale-mild` | under budget, 5-29 files OR 3-13 days | Fine to read, note it's slightly behind HEAD |
| `stale-major` | under budget, 30+ files OR 14+ days OR config file changed | Refresh via the `refresh-snapshot` skill before relying on it |

Only `too-large` triggers the `SessionStart` warning - nothing auto-reads
this file anymore, so a staleness nag about an artifact nobody reads is
noise, not signal.

## Why this is gitignored

Generated state, not source of truth, and it varies:

- Different developers have different working states
- Regeneration frequency depends on local activity
- Merging two copies would produce conflicts without benefit

If you need shared context across the team, commit `docs/CONSTITUTION.md` and `docs/architecture/` instead. Those are curated by humans.
